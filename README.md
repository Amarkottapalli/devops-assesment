# Docker Virtual Infrastructure with Ansible and a Hardened Nginx Reverse Proxy

Three Ubuntu containers (vm1, vm2, vm3) act as VMs. Ansible configures them, and Nginx on vm1 is an HTTPS reverse proxy with a load-balanced, health-checked route.

```
Mac -> Docker containers (vm1/vm2/vm3) -> SSH -> Ansible -> Nginx -> reverse proxy
```

## Repository layout

* `docker/` : Dockerfile, entrypoint.sh, docker-compose.yml
* `ansible/` : ansible.cfg, inventory.ini, site.yml, roles/ (common, ssh, firewall, nginx), group_vars/ (vault.yml is encrypted)
* `nginx/` : proxy.conf.j2 (vm1) and backend.conf.j2 (vm2/vm3)
* `docs/` : idempotency and failover evidence, screenshots

## Assumptions

* Docker Desktop for Mac cannot route to container IPs, so SSH and HTTP(S) ports are published on 127.0.0.1 (vm1: 2221, 80, 443; vm2: 2222; vm3: 2223) and the hosts file maps all three domains to 127.0.0.1. On Linux, map them to 172.20.0.11 to .13 instead.
* Containers have no systemd. The entrypoint starts the firewall, nginx and sshd, and Ansible starts services directly.
* "docker" is installed as the `docker.io` package, as the assignment asks. The daemon is not run inside the containers.
* Bootstrap user `devops` (key-only) is created in the Dockerfile. The playbook creates `ansible_user` with sudo through `/etc/sudoers.d/ansible_user`.
* The self-signed certificate is generated by Ansible on vm1 in `/etc/nginx/ssl/`, so no private key is in this repository.
* The vault passphrase is not committed. Create `ansible/.vault_pass` containing it (provided separately on request).
* Health checks are passive (`max_fails=2 fail_timeout=5s`), and upstreams use IPs because Nginx resolves names only at startup.
* Firewall: an iptables script generated by Ansible, re-applied on every container start (needs NET_ADMIN).

## Setup

1. Install Docker Desktop, then Ansible in a venv: `python3 -m venv ~/ansible-venv && source ~/ansible-venv/bin/activate && pip install ansible passlib`
2. Create a key: `ssh-keygen -t ed25519 -f ~/.ssh/devops_assessment -N ""`
3. Start the containers: `cd docker && docker compose up -d --build`
4. Add to `/etc/hosts`: `127.0.0.1 public.vm1.local`, `127.0.0.1 public.vm2.local`, `127.0.0.1 public.vm3.local`
5. Add Host entries for the three names to `~/.ssh/config` with Port 2221/2222/2223, User devops and the key above.
6. Create `ansible/.vault_pass`, then: `cd ansible && ansible all -m ping && ansible-playbook site.yml`

## Docker and SSH hardening

Custom network `labnet` (172.20.0.0/24) with static IPs .11 to .13, `restart: always`. sshd has `PasswordAuthentication no`, `PermitRootLogin no` and `AllowUsers devops ansible_user`. Tests: key login works, `ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password` is rejected, and root login is rejected.

## Domains and TLS

Domains `public.vm1.local`, `public.vm2.local` and `public.vm3.local` are set in the hosts file. The certificate command used by the nginx role:
`openssl req -x509 -nodes -newkey rsa:2048 -days 365 -keyout /etc/nginx/ssl/public.vm1.local.key -out /etc/nginx/ssl/public.vm1.local.crt -subj /CN=public.vm1.local -addext subjectAltName=DNS:public.vm1.local`

HTTP on port 80 returns 301 to HTTPS.

## Ansible

Key authentication is set in `ansible.cfg`. The `vms` inventory group contains all three VMs, with `proxy` and `backends` sub-groups. Roles: `common` (packages, ansible_user, sudoers.d), `ssh` (hardening plus handler), `firewall` (iptables script), `nginx` (install, certificate, configs). Secrets are in `group_vars/all/vault.yml`, encrypted with ansible-vault. Idempotency evidence: `docs/idempotency-run2.txt` (second run, `changed=0`).

## Nginx and dynamic page

Every VM serves `/` with hostname and time built per request from `$hostname` and `$time_iso8601`. There is no static file.

## Reverse proxy, health checks and failover

* `/vm2` goes to vm2, `/vm3` goes to vm3.
* `/app` goes to `upstream app_pool` (vm2 and vm3), with passive health checks and a 1 second connect timeout.
* Failover evidence: `docs/failover-test.txt` (vm2 stopped: traffic continues on vm3; vm2 restarted: it rejoins with no reload).

## Firewall rules (default-deny inbound)

| VM  | Open ports  | Source             |
| --- | ----------- | ------------------ |
| vm1 | 22, 80, 443 | anywhere           |
| vm2 | 22, 80      | 172.20.0.0/24 only |
| vm3 | 22, 80      | 172.20.0.0/24 only |

## Verification commands

`docker ps`, `ansible all -m ping`, `curl -I http://public.vm1.local`, `curl -k https://public.vm1.local/vm2`, and the `/app` loop shown in `docs/failover-test.txt`.
